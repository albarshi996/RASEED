# وثيقة المتطلبات الفنية والتنفيذية — رصيد | RASEED

> هذه الوثيقة هي المرجع الرسمي للمتطلبات كما قدّمها مالك المشروع. لا تُعدَّل إلا بموافقته.

- **مالك المشروع:** محمد إبراهيم البرشي
- **اسم النظام:** رصيد | RASEED — Smart Expense Management — «كل مصاريفك تحت السيطرة»
- **اللغة الأساسية:** العربية (RTL حقيقي)
- **العملة الأساسية:** الدينار الليبي (LYD)
- **الخلفية:** Firebase (مشروع `raseed-2fac1`)
- **المستودع:** https://github.com/albarshi996/RASEED
- **النوع:** تطبيق ويب احترافي متجاوب (هاتف + حاسوب)، قابل للتطوير لاحقًا إلى تطبيق مستقل.

---

## 1. الرؤية العامة

منظومة شخصية متكاملة لإدارة الجوانب المالية والشخصية والتنظيمية واليومية من مكان واحد.
ليست تطبيق تسجيل مصروفات بسيط، بل منصة ذكية مترابطة توفّر رؤية شاملة للوضع المالي والالتزامات
والديون والدخل ومصاريف المنزل والخطط المستقبلية والمهام والملاحظات ومتابعة العبادات.

**المبدأ الأساسي:** كل عملية تُسجَّل مرة واحدة، ثم ينعكس أثرها تلقائيًا على جميع الشاشات
والتقارير والأرصدة المرتبطة بها، دون تكرار البيانات أو تضارب الحسابات.

## 2. البنية التقنية

1. **Frontend:** React + TypeScript (مع Next.js إن كان مناسبًا).
2. **Backend:** Cloud Firestore + Firebase Authentication + Cloud Functions عند الحاجة.
3. **Storage:** Firebase Storage للمرفقات والإيصالات.
4. **Security:** Firebase Security Rules وفق هوية المستخدم وصلاحياته.
5. **Validation:** Zod أو ما يعادله.
6. **UI:** Tailwind CSS + مكتبة مكونات احترافية.
7. **Charts:** رسوم بيانية تفاعلية.
8. **PWA:** تثبيت على الهاتف + دراسة العمل دون اتصال والمزامنة.

يجب فصل منطق الأعمال والحسابات عن مكونات الواجهات وعن الوصول إلى Firebase.
هيكل واضح: مكونات قابلة لإعادة الاستخدام، خدمات مستقلة، أنواع بيانات دقيقة، معالجة أخطاء مركزية.

## 3. الهوية البصرية وتجربة الاستخدام

- واجهات عربية بالكامل باتجاه RTL حقيقي في كل الصفحات والجداول والقوائم والنوافذ.
- تصميم عصري هادئ فخم يعكس هوية تطبيق مالي شخصي، بلون أساسي يعبّر عن الثقة والاستقرار.
- دعم الوضع الفاتح والداكن.
- تنقل واضح على الحاسوب وشريط تنقل مناسب للهاتف.
- تصميم متجاوب، أيقونات موحدة، بحث وتصفية وفرز.
- رسائل تأكيد قبل العمليات الحساسة.
- حالات التحميل والنجاح والفشل وعدم وجود بيانات.
- تنسيق المبالغ بالدينار الليبي مع دعم الكسور العشرية.
- التاريخ الميلادي افتراضيًا، والهجري عند الحاجة (خصوصًا في قسم العبادات).

## 4. لوحة التحكم الرئيسية

ملخص حي ومباشر يشمل: إجمالي الأموال المتاحة، إجمالي الدخل الشهري، إجمالي المصروفات الشهرية،
صافي التدفق النقدي، الالتزامات القادمة، الالتزامات المتأخرة، إجمالي الديون المستحقة عليّ،
إجمالي المستحق لي لدى الآخرين، إجمالي مصروفات المنزل، المبالغ المخصصة للادخار،
نسبة استهلاك الميزانية الشهرية، مهام اليوم، التنبيهات المهمة.

رسوم بيانية: المصروفات حسب الفئة، مقارنة الإيرادات بالمصروفات، اتجاهات الإنفاق عبر الأشهر.
إمكانية تخصيص ترتيب البطاقات وإظهار/إخفاء بعضها، وزر سريع لإضافة مصروف أو دخل أو دين أو مهمة.

## 5. إدارة الحسابات والأرصدة

مصادر الأموال: النقد الشخصي، الحسابات المصرفية، المحافظ الإلكترونية، أي حساب آخر.
كل حساب: الاسم، النوع، الرصيد الافتتاحي، الرصيد الحالي، الحالة، سجل الحركات.
دعم التحويل بين الحسابات بخصم وإضافة مترابطين؛ التحويلات الداخلية ليست دخلًا ولا مصروفًا.
لا يُسمح بتعديل الرصيد الحالي يدويًا دون تسجيل عملية تسوية واضحة ومبررة.
الرصيد محسوب من الرصيد الافتتاحي + الحركات المعتمدة، مع ضمان عدم تكرار أثر أي حركة.

## 6. إدارة المصروفات اليومية

حقول المصروف: المبلغ، التاريخ، الفئة، الفئة الفرعية، الوصف، الحساب المدفوع منه، طريقة الدفع،
الجهة المستفيدة (اختياري)، مرفق/صورة إيصال، ملاحظات، تصنيف شخصي أو منزلي.

الفئات المقترحة: الطعام والمشروبات، المواصلات والوقود، مصاريف المنزل، المشتريات،
الاتصالات والإنترنت، الصحة، الترفيه، الهدايا، الاشتراكات، السفر، المصروفات الطارئة، فئات مخصصة.

إنشاء/تعديل/تعطيل الفئات دون الإضرار بالسجلات التاريخية.
مصروفات متكررة (يومي/أسبوعي/شهري) مع آلية تمنع إنشاء حركات مكررة عند تنفيذ الجدولة.

## 7. إدارة الدخل والإيرادات

مصادر: الراتب الشهري، المكافآت، الأعمال الإضافية، الإيرادات الاستثمارية، الهدايا المالية، أخرى.
كل عملية: المصدر، المبلغ، التاريخ، الحساب المستلم، الوصف، المرفقات.
دعم الدخل المتكرر والمتوقع، والتمييز بين المتوقع والمستلم فعليًا.
**لا تُضاف المبالغ المتوقعة إلى الرصيد المتاح قبل تسجيل استلامها.**

## 8. إدارة الالتزامات المالية

أمثلة: إيجار المنزل، الكهرباء والمياه، الإنترنت والهاتف، الأقساط، الاشتراكات، الالتزامات العائلية.
لكل التزام: الاسم، الجهة المستفيدة، القيمة الإجمالية، تاريخ الاستحقاق، دورية التكرار،
المبلغ المسدد، المبلغ المتبقي، الأولوية، الحالة، ملاحظات ومرفقات.
الحالات: قادم، مستحق، متأخر، مسدد جزئيًا، مسدد بالكامل، ملغى.
دعم السداد الجزئي وتحديث المتبقي تلقائيًا، وإنشاء حركة مالية مرتبطة عند الدفع الفعلي.
تنبيهات قبل الاستحقاق، وفي يومه، وبعد التأخر.

## 9. إدارة الديون المستحقة عليّ

اسم الدائن، قيمة الدين، تاريخ النشوء، تاريخ السداد المتوقع، الأقساط، المدفوع، المتبقي.
سجل لجميع الدفعات وإمكانية إرفاق إثبات السداد.
احتساب الإجمالي والترتيب حسب الأولوية وموعد الاستحقاق.
**لا يُخصم الدين من الرصيد النقدي بمجرد تسجيله إذا لم يُدفع مبلغ فعلي**؛ يُعرض كالتزام،
مع تسجيل أي مبلغ مستلم أو مدفوع بحسب طبيعته.

## 10. إدارة الديون المطلوب تحصيلها

اسم المدين، رقم الهاتف (اختياري)، قيمة الدين، تاريخ الدين، موعد التحصيل، المبلغ المحصل،
الرصيد المتبقي، حالة التحصيل، سجل المتابعات، الملاحظات والمرفقات.
تحصيل جزئي أو كامل مع تحديث رصيد الحساب عند الاستلام.
إظهار الديون المتأخرة والتحصيل المتوقع خلال الأسبوع والشهر.
تسجيل ملاحظات متابعة مع كل شخص وتحديد موعد للتواصل.

## 11. إدارة مصاريف المنزل

قسم متخصص مرتبط بالنظام المالي العام: ميزانية المنزل الشهرية، المواد الغذائية، مستلزمات التنظيف،
فواتير الخدمات، الصيانة، الأثاث والأجهزة، الاحتياجات العائلية، المصاريف الموسمية، الطارئة.
مقارنة الميزانية المعتمدة بالمصروف الفعلي والمتبقي.
**تظهر مصاريف المنزل في التقارير العامة دون تكرار قيمتها**؛ هذا القسم طريقة عرض متخصصة
للمصروفات المنزلية نفسها.

## 12. التخطيط المالي والميزانيات

ميزانية شهرية عامة، سقف إنفاق لكل فئة، أهداف ادخار، أهداف مالية (سيارة/منزل/صندوق طوارئ)،
قيمة الهدف والمبلغ المدخر والمدة المتوقعة، نسبة تقدم تلقائية، مقارنة الفعلي بالخطة،
توقعات التدفقات النقدية، تنبيه عند الاقتراب من تجاوز الميزانية.
سيناريوهات مالية (انخفاض الدخل / ارتفاع المصروفات بنسبة).
**فصل واضح بين البيانات الفعلية والتوقعات والافتراضات.**

## 13. المفكرة الشخصية

ملاحظات يومية، دفاتر/تصنيفات، أفكار وخطط، تدوين القرارات، قوائم متابعة، بحث داخل الملاحظات،
تثبيت المهم، الأرشفة، تاريخ الإنشاء والتعديل.
محرر نصوص مريح يدعم العناوين والقوائم والتنسيق الأساسي.
ربط اختياري بمهمة أو هدف مالي أو التزام.

## 14. إدارة المهام والتذكيرات

مهام يومية/أسبوعية/شهرية/متكررة/مرتبطة بتاريخ، أولويات، حالات، قوائم مهام،
المكتملة والمتأخرة، ملاحظات التنفيذ.
عرض في قائمة وتقويم مع تصفية حسب التاريخ والأولوية والحالة.
تنبيهات داخل التطبيق + إشعارات المتصفح عند منح الإذن + Firebase للإشعارات عند الحاجة.
**لا تُعرض مهمة كمكتملة دون إجراء إكمال صريح من المستخدم.**

## 15. قسم العبادات والتنظيم الروحي

قسم شخصي هادئ ومحترم:
1. **متابعة الصلاة:** الصلوات الخمس يوميًا مع تسجيل الأداء والحالة والملاحظات، ومتابعة أسبوعية وشهرية.
   لاحقًا: مواقيت الصلاة وفق المدينة والموقع وطريقة الحساب، دون أوقات ثابتة أو تقديرية غير موثوقة.
2. **قراءة القرآن:** متابع للورد اليومي (سورة/آيات/صفحات)، هدف يومي، تقدم أسبوعي وشهري.
   عند إضافة النص الكامل: مصدر موثوق ومراجَع (دقة النص والتشكيل وترقيم الآيات).
3. **الأذكار والأعمال الصالحة:** أذكار الصباح والمساء، الاستغفار، الصدقة، الصيام التطوعي، وغيرها.
   متابعة شخصية دون أحكام أو تقييمات دينية على المستخدم.
4. **الزكاة والصدقات:** الأموال الخاضعة للزكاة، الالتزامات ذات الصلة، تاريخ الحول، النصاب، المدفوع.
   حاسبة زكاة إرشادية مع توضيح الطريقة والافتراضات والمصادر، وليست فتوى نهائية.
   **فصل احتساب الزكاة عن تسجيل دفعها ماليًا**، فلا يُخصم مبلغ دون دفع فعلي.

## 16. التقارير والتحليلات

تقارير: يومي، أسبوعي، شهري، سنوي، الدخل، المصروفات، الديون عليّ، الديون لي، الالتزامات
القادمة والمتأخرة، مصاريف المنزل، الميزانية والانحرافات، الادخار والأهداف، حركة الحسابات،
التدفق النقدي، المهام والإنجازات، متابعة العبادات.
اختيار الفترة والتصفية حسب الحساب والفئة والحالة، جداول ورسوم، تصدير Excel/PDF/CSV.
**جميع الأرقام من البيانات الفعلية، وليست قيمًا تجريبية ثابتة.**

## 17. التنبيهات الذكية

مركز موحّد: التزامات تستحق قريبًا، ديون تأخر سدادها، مبالغ حان تحصيلها، تجاوز الميزانية،
اقتراب موعد هدف مالي، المهام المتأخرة، التذكيرات اليومية، تذكيرات العبادات الاختيارية.
لكل تنبيه: حالة قراءة، مستوى أهمية، رابط للسجل المرتبط.
إعدادات تفعيل/إيقاف لكل نوع، ومنع التنبيهات المكررة وغير الضرورية.

## 18. تصميم قاعدة بيانات Firebase

تنظيم ضمن نطاق المستخدم المصادق عليه `users/{uid}` ومجموعات تشمل:
`profiles, accounts, transactions, categories, obligations, debts, debtPayments, contacts,
budgets, financialGoals, notes, tasks, reminders, notifications, worshipRecords, quranProgress,
zakatRecords, attachments, auditLogs, settings`.
يمكن تعديل الهيكل إذا كان هناك تصميم أفضل، بشرط توثيق الأسباب والعلاقات.

كل سجل: معرف فريد، معرف مالك السجل، تاريخ الإنشاء، تاريخ آخر تعديل، الحالة، بيانات العملية، المراجع.

**المتطلبات الجوهرية:**
1. توحيد أنواع البيانات بـ TypeScript.
2. التحقق من المدخلات قبل الكتابة.
3. تخزين المبالغ بوحدات نقدية صغرى صحيحة (أو آلية دقيقة مكافئة) لتجنب أخطاء الكسور.
4. استخدام Firestore Transactions أو Batched Writes حسب طبيعة العملية.
5. منع تكرار المعاملات المالية بمعرفات عمليات ثابتة.
6. قواعد واضحة للحذف والتعديل والأرشفة.
7. إنشاء الفهارس المطلوبة.
8. آلية ترحيل لتغييرات المخطط.
9. سجلات تدقيق للتعديلات المالية الحساسة.
10. آلية آمنة للمعاملات التي تحدّث أكثر من سجل.

**أهم شرط:** عند تسجيل عملية مالية يجب أن يظهر أثرها الصحيح على الحسابات والتقارير
والالتزامات والأهداف المرتبطة، دون ازدواج أو فقدان بيانات.

## 19. قواعد الأعمال والمحاسبة

- المصروف المدفوع يخفض رصيد الحساب.
- الدخل المستلم يرفع رصيد الحساب.
- التحويل بين حسابين لا يغيّر إجمالي الأموال المملوكة.
- إنشاء التزام غير مدفوع لا يخفض الرصيد النقدي.
- دفع التزام يخفض الرصيد ويسجل الدفعة المرتبطة.
- تسجيل دين على المستخدم لا يعني بالضرورة حركة نقدية.
- تحصيل دين يرفع رصيد الحساب المستلم.
- سداد دين يخفض رصيد الحساب المستخدم للدفع.
- المبالغ المستحقة للتحصيل لا تُعرض ضمن النقد المتاح.
- تعديل/إلغاء عملية معتمدة يتم بطريقة تحفظ الأثر التاريخي وتمنع تضارب الأرصدة.
- التمييز بين التحويلات والاقتراض والسداد والدخل الحقيقي والمصروف الحقيقي حتى لا تتضخم التقارير.

قواعد لمنع: المبالغ السالبة غير المسموح بها، السداد الزائد عن المستحق، التكرار، العمليات غير المكتملة.

## 20. الأمن والخصوصية

Firebase Authentication؛ منع الوصول دون تسجيل دخول؛ Firestore + Storage Security Rules حقيقية
ومنشورة؛ عزل بيانات كل مستخدم؛ عدم اعتبار إخفاء عناصر الواجهة حماية؛ عدم تخزين مفاتيح إدارية
في كود الواجهة؛ Cloud Functions للعمليات الموثوقة؛ التحقق من ملكية المستندات والمرفقات؛
حدود أحجام وأنواع الملفات؛ تصدير واستعادة البيانات؛ استراتيجية نسخ احتياطي؛ إدارة الجلسات.

المشروع شخصي حاليًا، لكن الهيكل يجب أن يسمح بإضافة مستخدمين مستقبلًا دون إعادة تصميم قاعدة البيانات.

## 21. الإعدادات الشخصية

الاسم، الصورة، اللغة، العملة، تنسيق التاريخ، الوضع الليلي، إعدادات التنبيهات، بداية الشهر المالي،
فئات المصروفات، الحسابات الافتراضية، إعدادات الخصوصية، تصدير البيانات، إعدادات الأمان.
محفوظة في Firebase ومتزامنة بين الأجهزة.

## 22. الأداء والمزامنة

تحميل المطلوب فقط، Pagination، تجنب الاستعلامات المكلفة، تحديث العرض بعد الحفظ دون إعادة تحميل،
حالات واضحة عند انقطاع الاتصال، معالجة تعارضات التعديل، عدم اعتبار العملية محفوظة إلا بعد تأكيد
نجاح الكتابة، اختبار التزامن بين الهاتف والحاسوب، مراعاة تكلفة القراءة والكتابة في Firebase.

1. **التحليل والتأسيس:** مراجعة القائم، المتطلبات والكيانات والعلاقات، الهيكل البرمجي،
   إعداد Firebase، قواعد الأمان، الهوية البصرية والمكونات الأساسية.
2. **النظام المالي الأساسي:** الحسابات والأرصدة، المصروفات، الدخل، التحويلات، الفئات،
   لوحة التحكم الأساسية، التقارير المالية الأولية.
3. **الالتزامات والديون:** الالتزامات، الديون عليّ، الديون لي، الدفعات والتحصيلات، التنبيهات المالية.
4. **المنزل والتخطيط المالي:** مصاريف المنزل، الميزانيات، الادخار، الأهداف، التوقعات.
5. **التنظيم الشخصي:** المفكرة، المهام، التقويم، التذكيرات، مركز التنبيهات.
6. **العبادات:** الصلاة، القرآن، الأذكار، الزكاة والصدقات.
7. **التقارير المتقدمة:** الرسوم، التفصيلية، التصدير، المقارنات، التحليلات.
8. **المراجعة والتسليم:** اختبارات شاملة، إصلاح الأخطاء، مراجعة الأمان، تحسين الأداء، التوثيق،
   نسخة مستقرة.

## 25. تعليمات تنفيذية إلزامية

1. التعامل مع المشروع كنظام حقيقي قابل للاستخدام اليومي، لا نموذج تجريبي.
2. فحص الملفات الحالية قبل إنشاء بدائل أو تغيير الهيكل.
3. عدم حذف أي وظيفة قائمة دون فهم أثرها والحصول على موافقة المالك.
4. عدم استخدام بيانات وهمية على أنها حقيقية.
5. لا شاشة دون تحديد مصدر بياناتها وآلية الحفظ والتحديث.
6. لا عمليات مالية دون تحديد أثرها المحاسبي.
7. عدم تكرار منطق الحسابات في عدة ملفات.
8. مكونات قابلة للصيانة والتوسع.
9. عدم وضع أسرار Firebase أو مفاتيح إدارية في الواجهة.
10. Security Rules ليست جاهزة لمجرد كتابتها؛ تُختبر وتُنشر بعد الموافقة.
11. عدم نشر تغييرات إنتاجية أو تعديل بيانات حقيقية قبل مراجعة الأثر والموافقة.
12. سلامة البيانات عند كل تحديث.
13. فحص الأخطاء بعد كل مرحلة.
14. توثيق أي قرار معماري مهم.
15. شرح السبب الجذري والحل عند اكتشاف مشكلة، لا إخفاء رسالة الخطأ.
16. عدم إعلان اكتمال ميزة إلا بعد ربطها فعليًا واختبارها.
17. التوافق بين شاشات النظام.
18. جميع النصوص ورسائل الأخطاء بالعربية الواضحة.
19. الدينار الليبي عملة افتراضية في جميع الشاشات والتقارير.
20. «محمد إبراهيم البرشي» مالك المشروع في البيانات التعريفية، قابل للتعديل من الإعدادات.

## 26. المخرجات المطلوبة

هيكل معماري، مخطط قاعدة البيانات والعلاقات، قواعد الأعمال المالية، نظام تصميم موحد،
واجهات احترافية متجاوبة، خدمات Firebase، قواعد الأمان والفهارس، نظام التقارير، نظام التنبيهات،
اختبارات موثقة، ملف إعدادات البيئة، دليل التشغيل والنشر، توثيق لكل مرحلة،
قائمة بما نُفِّذ وما لم يُنفَّذ، تقرير نهائي بنتائج الاختبارات والأخطاء المتبقية.
